# 文件传输前端交互调整方案

## 1. 文档目的

本文档用于约定 DAVEX Center 前端“数据流通 → 文件传输”页面的交互调整方案，作为后续代码实现和验收依据。

本次调整的核心目标是：用户完成服务器间文件传输后，可以直接在当前页面将文件下载到浏览器，不再必须进入“结果管理区 → 文件传输”页面。

本文档同时记录最终落地方案与验收依据。

## 2. 当前交互

当前文件传输流程如下：

1. 用户进入“数据流通 → 文件传输”。
2. 用户选择代理并浏览该代理的目录。
3. 用户在文件列表中点击“获取文件”。
4. Center 调用文件传输接口，将 Agent 的文件保存到 Center 结果管理区。
5. 前端显示“文件传输完成”弹窗。
6. 用户进入“结果管理区 → 文件传输”。
7. 用户在结果列表中再次点击“获取文件”，才能取得文件。

主要问题：文件已经完成服务器间传输，但用户仍需切换导航和页面才能继续获取文件，操作链路较长。

## 3. 调整目标

### 3.1 目标

- 保持当前页面的整体布局、表格、按钮和弹窗风格不变。
- 文件仍按现有逻辑从 Agent 传输到 Center 服务器。
- 传输过程中明确展示加载状态，防止用户重复提交。
- 传输成功后，在当前页面提供“立即下载”按钮。
- 点击“立即下载”后，将文件下载到用户浏览器。
- 文件仍保存在结果管理区，便于后续统一查看、预览、获取或删除。

### 3.2 不在本次范围内

- 不修改“结果管理区 → 文件传输”页面的布局和功能。
- 不合并数据流通页和结果管理页。
- 不修改现有路由和导航结构。
- 不调整其他数据流通功能。
- 不进行整体视觉重构。

## 4. 目标交互流程

调整后的流程如下：

1. 用户进入“数据流通 → 文件传输”。
2. 用户选择代理并找到目标文件。
3. 用户点击文件行中的“传输文件”按钮。
4. 前端立即显示加载框，提示“文件传输中，请稍候……”。
5. 前端调用服务器间文件传输接口。
6. 接口成功返回后，关闭加载框并展示成功弹窗。
7. 成功弹窗提供：
   - “文件预览”：在当前页面预览本次传输完成的文件。
   - “立即下载”：将本次传输完成的文件下载到浏览器。
8. 下载操作不删除结果记录，用户之后仍可在结果管理区操作该文件。

```text
选择文件
  → 传输文件
  → 显示加载框
  → 文件保存到 Center 结果管理区
  → 显示传输成功弹窗
  → 立即下载到浏览器（可选）
```

## 5. 页面调整

目标页面：

`DAVEX_ui/src/views/datashare/fileTrans.vue`

### 5.1 文件操作按钮

- 将当前“获取文件”按钮文案调整为“传输文件”，更准确地表达 Agent 到 Center 的服务器间传输行为。
- 按钮继续使用现有 `small-default-button` 样式。
- 文件正在传输时禁止重复点击。

### 5.2 传输加载状态

用户点击“传输文件”后显示 Element Plus 加载框。

加载框要求：

- 提示文字为“文件传输中，请稍候……”。
- 传输完成前不可重复发起同一操作。
- 无论请求成功或失败，都必须关闭加载框。
- 加载期间保留当前代理、目录和文件列表状态。

### 5.3 传输成功弹窗

传输完成后继续使用现有成功弹窗样式，内容调整为：

```text
文件传输完成，文件已保存到结果管理区。
```

弹窗底部提供两个按钮：

- “文件预览”：打开独立预览弹窗，并按纯文本展示文件内容。
- “立即下载”：下载刚完成传输的文件。

本流程不再要求用户跳转到结果管理区。

### 5.4 传输失败

- 保留现有失败弹窗。
- 显示后端返回的失败信息。
- 关闭加载状态并恢复“传输文件”按钮。
- 失败时不显示“立即下载”。

### 5.5 下载状态

- 用户点击“立即下载”后，按钮进入加载状态，避免重复下载。
- 下载成功后关闭成功弹窗，并显示轻量成功提示。
- 下载失败时保留弹窗，并展示明确错误提示，允许用户重试。

## 6. 接口使用

本方案优先复用现有接口，不新增业务接口。

### 6.1 服务器间文件传输

```http
POST /file/getFile
Content-Type: application/x-www-form-urlencoded
```

参数：

| 参数 | 来源 | 说明 |
|---|---|---|
| `fileId` | 当前文件行 `uid` | Agent 上的文件 ID |
| `agentId` | 当前文件行 `agentId` | 文件所属 Agent |
| `folderId` | 当前文件行 `parentId` | 文件所在目录 ID |
| `applicationId` | 当前页面配置 | Center 应用 ID |

该接口成功返回时，文件已经保存到 Center 结果管理区。

### 6.2 定位本次传输结果

当前 `/file/getFile` 成功响应只返回文字信息，没有返回结果管理区的 `outputId`，而浏览器下载接口需要 `outputId`。

为控制本次改动范围，前端在传输成功后调用：

```http
POST /file/query
Content-Type: application/x-www-form-urlencoded
```

查询当前 `applicationId` 的结果文件，并按以下条件定位本次传输结果：

1. `fileId` 等于本次选择文件的 `uid`。
2. `agentId` 等于本次选择文件的 `agentId`。
3. 如果存在多条匹配记录，选择 `uploadDate` 最新的一条。

匹配成功后保存该记录的 `uid`，作为下载所需的 `outputId`。

如果未找到匹配记录，则传输仍视为成功，但“立即下载”应提示“暂未定位到传输结果，请稍后在结果管理区下载”，不得传入错误的 `outputId`。

### 6.3 浏览器下载

```http
POST /file/fetchByHttp
Content-Type: application/x-www-form-urlencoded
```

参数：

| 参数 | 说明 |
|---|---|
| `outputId` | 本次传输结果的 ID |
| `applicationId` | 当前应用 ID |

前端请求要求：

- Axios 使用 `responseType: 'blob'`。
- 从响应头 `Content-Disposition` 中获取文件名；无法获取时使用原文件名。
- 使用临时对象 URL 和隐藏 `<a>` 元素触发浏览器下载。
- 下载触发后释放临时对象 URL。

### 6.4 文件预览

```http
POST /file/read
Content-Type: application/x-www-form-urlencoded
```

参数与浏览器下载一致，使用本次传输结果的 `outputId` 和当前 `applicationId`。预览内容使用纯文本渲染并保留换行，不使用 `v-html`，避免文件内容被浏览器当作 HTML 执行。

## 7. 前端代码预计调整范围

预计只修改以下文件：

1. `DAVEX_ui/src/views/datashare/fileTrans.vue`
   - 增加传输加载状态。
   - 保存当前传输文件信息。
   - 调整成功弹窗按钮。
   - 增加结果定位、文件预览和立即下载逻辑。
2. `DAVEX_ui/src/api/direct.js`
   - 复用现有结果查询方法。
   - 增加 `/file/fetchByHttp` 的 Blob 下载请求封装。

“结果管理区 → 文件传输”对应组件不做修改。

## 8. 状态与异常处理

| 状态 | 页面表现 | 可执行操作 |
|---|---|---|
| 初始状态 | 展示代理和文件列表 | 选择代理、浏览目录、传输文件 |
| 传输中 | 显示加载框 | 等待，不允许重复传输 |
| 传输成功 | 显示成功弹窗 | 文件预览或立即下载 |
| 结果定位失败 | 显示提示信息 | 关闭弹窗，之后前往结果管理区操作 |
| 下载中 | “立即下载”按钮加载 | 等待，不允许重复下载 |
| 下载失败 | 显示下载失败信息 | 重试或关闭 |
| 传输失败 | 显示现有失败弹窗 | 关闭后重新操作 |

## 9. 接口风险与验证点

`/file/fetchByHttp` 当前后端实现会直接向 `HttpServletResponse` 写入文件流，同时 Controller 仍声明返回统一响应对象。实现阶段需要实际验证浏览器收到的内容是否为完整文件。

如果出现响应已提交、文件尾部混入 JSON 或文件损坏，只对该下载接口做最小后端修正：下载成功时直接结束响应，不再向同一个响应体追加 JSON。该修正需要另行确认后再实施，不属于本前端方案的默认改动范围。

## 10. 验收标准

- “数据流通 → 文件传输”页面原有布局和视觉风格基本不变。
- 用户点击“传输文件”后能看到明确的加载状态。
- 加载期间不会重复提交同一文件传输请求。
- 传输成功后仍能在结果管理区查询到文件。
- 成功弹窗包含“文件预览”按钮，预览内容和换行正确。
- 成功弹窗包含“立即下载”按钮。
- 用户无需切换到结果管理区即可触发浏览器下载。
- 下载文件名称和内容正确。
- 关闭弹窗后仍停留在原代理和目录位置。
- 传输失败或下载失败时加载状态能够正确结束，并显示可理解的错误信息。
- 结果管理区现有页面和功能不受影响。

## 11. 后续可选优化

如果后续允许调整后端契约，可让 `/file/getFile` 在成功响应中直接返回结果记录的 `outputId`、文件名和上传时间。前端即可直接下载，不再需要调用 `/file/query` 查找最新结果。

该优化不包含在本次前端交互调整范围内。
